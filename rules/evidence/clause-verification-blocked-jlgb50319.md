## 二、为什么本轮取不到条文

公告页所附规范正文 PDF（`1438056268205337-1723956558529709.pdf`，7.4 MB）已下载并解包检查：

| 检查项 | 结果 |
|---|---|
| 页数 | 63 |
| 内嵌图片 | **500 张** |
| 可提取的非空文本行 | **126 行** |
| 那 126 行的内容 | 全部是重复页眉（"住房和城乡建设部信息中心""标准专区"之类） |

**结论：该 PDF 是扫描件，没有文字层。** 因此无法通过文本提取获得逐字条文。

## 三、为什么不用 OCR 补齐

本案**明确不采用 OCR**，理由是它直接违反本规则库的核心纪律：

- OCR 输出**必然带有识别错误**（形近字、标点、上下标），而本规则库要求
  `excerpt` 是**逐字摘录、不得改写**；
- 用 OCR 结果充当"逐字条文"，等于把**识别不确定性**伪装成**引文确定性**——
  这正是 `rules/evidence/` 这套记录要防的事；
- 且本插件核对的是**监理台账的齐备与自洽**，条文用词的细微差别（如"应"与"宜"）
  在监理语境下足以改变结论，OCR 错字会直接误导读者。

```sh
curl -sL -A 'Mozilla/5.0' 'https://www.dengzhou.gov.cn/2024/09-05/1180935.html' \
  | sed 's/<[^>]*>//g' | tr -s ' ' | grep -o 'GB/T50319-2013[^。]*'
# 2) 附件 PDF（证明无文字层）
curl -sL -o jlgb.pdf 'https://oss.nanyang.gov.cn/nanyang_dengzhou/zjj/rootfiles/2024/09/05/1438056268205337-1723956558529709.pdf'
python -c "import pymupdf; d=pymupdf.open('jlgb.pdf'); print(d.page_count, sum(len(p.get_images()) for p in d), len(''.join(p.get_text() for p in d)))"
# 预期输出：63 500 1448 —— 页数大、图片多、文本极少
```
